# Техническое задание (ТЗ): Crystal-Core VPS Install Manager

## 1. Общие сведения
* **Наименование продукта:** Crystal-Core VPS Install Manager (`vps-setup`).
* **Назначение:** Автоматизированная первичная настройка, обновление и аудит состояния серверов под управлением Ubuntu LTS (22.04 / 24.04 и выше) в интерактивном (TUI) и неинтерактивном (CLI) режимах.
* **Целевая платформа:** Linux (`amd64`, `arm64`), Ubuntu Server.
* **Стек технологий:** Go 1.24+, `github.com/charmbracelet/huh`, `github.com/charmbracelet/lipgloss`, стандартная библиотека Go (`embed`, `text/template`, `net/http`, `encoding/json`, `flag`).

## 2. Цели разработки
1. Сократить время первичной подготовки Ubuntu VPS с графическим интерфейсом, защитой и AI-инструментами до одного запуска бинарника.
2. Исключить типовые ошибки ручной настройки: блокировку SSH при отключении `root`/паролей, черный экран в XRDP, навязчивые окна `polkit`/`colord`, открытый в интернет порт `3389`.
3. Обеспечить идемпотентность: повторный запуск утилиты должен безопасно обновлять пакеты и доустанавливать недостающие модули без дублирования конфигов.

## 3. Архитектурные требования
* **Распространение:** единый статически скомпилированный бинарный файл (`CGO_ENABLED=0`) без внешних runtime-зависимостей.
* **Хранение конфигураций:** все шаблоны и статические конфиги (`45-allow-colord.rules`, `jail.local.tmpl`, `kitty.conf`, `zshrc.snippet`, `daemon.json`) встраиваются в бинарник через `//go:embed configs/*`.
* **Логирование:** весь `stdout`/`stderr` выполняемых системных команд перенаправляется в `/var/log/vps-setup.log`.
* **Контекст пользователя:** целевой пользователь определяется по приоритету: флаг `--user` -> переменная `SUDO_USER` -> текущий пользователь. При выполнении `create_user` контекст (`TargetUser`, `TargetHome`) динамически переключается на нового пользователя.

## 4. Функциональные требования
* **Брендинг:** при запуске (кроме `--status --json`) выводится баннер Crystal-Core с Unicode-кристаллом, описанием услуг автоматизации бизнеса и контактами (`https://crystal-core.com/`, `info@crystal-core.com`).
* **19 модулей установки** (в порядке выполнения): `create_user`, `update`, `swap`, `xfce`, `xrdp`, `panel_launcher`, `browser`, `ru_layout`, `kitty_fonts`, `zsh_starship`, `bbr`, `tailscale`, `ssh_hardening`, `fail2ban_ufw`, `unattended`, `ai_cli`, `docker`, `ollama`, `upgrade_ubuntu`.
* **Порядок выполнения** фиксирован и не зависит от порядка выбора: первый запуск обычно идёт на сервере без графики, поэтому рабочий стол и RDP ставятся первыми, а `upgrade_ubuntu` (переход на новую LTS, требует перезагрузки) — последним.
* **Быстрый старт:** при отсутствии XFCE/XRDP меню по умолчанию предлагает набор `create_user` (под root), `swap`, `xfce`, `xrdp`, `panel_launcher`, `browser`, `ru_layout`; в CLI — `--preset rdp`.
* **Сведения о сервере:** при запуске (кроме `--version` и `--status --json`) выводятся версия ОС и ядра, архитектура, процессор и число ядер, ОЗУ и swap, диски (`lsblk`) и заполненность `/`.
* **Главное меню:** «Быстрый старт», «Полная настройка», «Удаление установленных компонентов», «Состояние модулей», «Выход». Из каждого подменю — возврат в главное меню по `Esc` и явным пунктом «← Назад».
* **Удаление:** выборочно или всё (`--remove <list|all>`), в обратном порядке. Удаляются только модули, установленные программой, и только пакеты, которых не было до установки (учёт в `/var/lib/vps-setup`); исходные настройки восстанавливаются. `update` и `upgrade_ubuntu` не удаляются.
* **Значки на нижней панели XFCE:** программы, установленные модулями (сама программа — `panel_launcher`, Kitty — `kitty_fonts`, Claude Code / Codex / OpenCode / Gemini CLI / Aider — `ai_cli`), регистрируются в `/usr/share/vps-setup/panel`; `panel.sh sync` добавляет их значки после стандартных ярлыков нижней панели (в открытых сессиях — сразу, в новых — при входе, каждый значок один раз) и убирает значки удалённых программ. Консольные программы запускаются со значка через скрипты `/usr/local/lib/vps-setup/apps/<программа>` (одна команда без аргументов — так её одинаково принимает любой терминал). Бинарник копируется в `/usr/local/bin/vps-setup`; при каждом запуске от root программа исправляет значки и helper Kitty, установленные версиями до 1.2.1.
* **Обновление из меню:** пункт «Обновить программу»; последняя версия запрашивается в фоне при запуске, версии сравниваются по semver; после обновления (с проверкой SHA-256) программа перезапускается в новой версии.
* **CLI-режимы:** `--status`, `--json`, `--preset`, `--only`, `--remove`, `--new-user` (+ `VPS_SETUP_PASSWORD`), `--user`, `--ssh-port`, `--auto-reboot`, `--dry-run`, `--self-update`, `--version`.

## 5. Требования к безопасности и надежности
* Пароль нового пользователя передается через `stdin` в `chpasswd` (исключение утечки в `ps aux` и логах).
* Запрещено отключение парольной аутентификации SSH при отсутствии валидного `~/.ssh/authorized_keys` и при целевом пользователе `root`; проверка выполняется до начала установки.
* Порт SSH по умолчанию не меняется; при смене новый порт открывается в UFW/iptables до перезапуска sshd. UFW разрешает фактические порты sshd.
* Ключи, переносимые новому пользователю, очищаются от опций `command="..."` (заглушки root в облачных образах).
* `--self-update` проверяет SHA-256 по `checksums.txt` релиза.
* Все Bash-скрипты выполняются в строгом режиме `bash -euo pipefail`.
