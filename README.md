# Crystal-Core VPS Install Manager

<p align="center">
  <img src="assets/icon.png" alt="Crystal-Core VPS Install Manager" width="180" />
</p>

**Crystal-Core VPS Install Manager** (`vps-setup`) — интерактивный TUI- и CLI-установщик на Go (Charmbracelet) для быстрой, безопасной и воспроизводимой настройки Ubuntu VPS под ключ: от обновления ОС и харденинга SSH до графической среды XFCE + XRDP, Docker и AI CLI-инструментов.

> **Crystal-Core — Автоматизация бизнеса и IT-инфраструктура под ключ**  
> Заказная разработка, AI-агенты, интеграции и настройка серверов.  
> Сайт: [crystal-core.com](https://crystal-core.com/) | Почта: [info@crystal-core.com](mailto:info@crystal-core.com)

## Возможности

* **Один статический бинарник:** без внешних зависимостей, все конфиги вшиты через `//go:embed`.
* **Сначала рабочий стол и RDP:** на «голом» сервере установщик сам предлагает *быстрый старт* — пользователь, swap, XFCE, XRDP и раскладка. Модули всегда выполняются в фиксированном порядке: рабочий стол и RDP первыми, тяжёлые и рискованные шаги — в конце. Подключаться по RDP можно сразу после модуля `xrdp`, пока ставится остальное.
* **Умное TUI-меню:** автоматически определяет уже установленные модули, помечает их `[установлено]` и снимает с них галочки при повторном запуске.
* **Безопасность по умолчанию:** создание `sudo`-пользователя с переносом SSH-ключей, харденинг SSH с проверками от блокировки, Fail2Ban, UFW и RDP строго через SSH-туннель или Tailscale.
* **Автоматизация и CI/CD:** неинтерактивный режим (`--preset`, `--only`, `--new-user`, `--user`, `--auto-reboot`), пробный прогон (`--dry-run`) и мониторинг (`--status --json`).
* **Самообновление:** обновление бинарника из GitHub Releases с проверкой `checksums.txt` (`--self-update`).

## Модули установки

Модули перечислены **в порядке выполнения**; порядок не зависит от того, как их отметили или перечислили в `--only`.

| # | ID | Модуль | Описание | По умолч. |
|---|---|---|---|---|
| 1 | `create_user` | Создать sudo-пользователя | Новый аккаунт с паролем для `sudo`/XRDP, SSH-ключи из `/root` и от пользователя `sudo` (без опций `command="..."` облачных образов) | Вкл (под root) |
| 2 | `update` | Обновление пакетов + CLI-утилиты | `apt upgrade`, `curl`, `wget`, `git`, `htop`, `btop`, `tmux`, `unzip`, `net-tools`, `fontconfig`, `gnupg` | Вкл |
| 3 | `swap` | Swap-файл 2 ГБ | `/swapfile` с записью в `/etc/fstab` — до установки XFCE, чтобы хватило памяти | Вкл |
| 4 | `xfce` | XFCE | Рабочий стол, удаление `xfce4-screensaver`/`light-locker` (фикс черного экрана), отключение локального дисплей-менеджера | Вкл |
| 5 | `xrdp` | XRDP | RDP на `127.0.0.1:3389` (или на `tailscale0`), фикс `startwm.sh` и `polkit` для Ubuntu 22.04 и 24.04; задаёт пароль, если у пользователя его нет | Вкл |
| 6 | `ru_layout` | Русская раскладка | Локаль `ru_RU.UTF-8`, переключение `us,ru` по `Alt+Shift` | Вкл |
| 7 | `kitty_fonts` | Kitty + Nerd Fonts | Kitty — терминал по умолчанию в XFCE, шрифты `JetBrainsMono` и `FiraCode` | Вкл |
| 8 | `zsh_starship` | Zsh + Starship | Zsh по умолчанию, промпт `nerd-font-symbols`, автодополнение и подсветка | Вкл |
| 9 | `bbr` | TCP BBR | `bbr` + `fq` в `sysctl` для плавной работы RDP | Вкл |
| 10 | `tailscale` | Tailscale | Приватная mesh-сеть для прямого доступа к RDP без SSH-туннеля | Выкл |
| 11 | `ssh_hardening` | Харденинг SSH | Запрет `root` и паролей; смена порта — только если задана явно | Вкл |
| 12 | `fail2ban_ufw` | Fail2Ban + UFW | Защита SSH, закрытие всех портов, кроме реальных портов sshd (и `3389/tcp` на `tailscale0`) | Вкл |
| 13 | `unattended` | Автообновления | Фоновая установка патчей безопасности | Вкл |
| 14 | `ai_cli` | AI CLI-инструменты | Claude Code, Codex, OpenCode, Gemini CLI, Aider + Node.js 22, `uv`, `gh`, `ripgrep`, `fd-find`, `jq` | Вкл |
| 15 | `docker` | Docker Engine | Docker CE, Compose v2, Buildx, группа `docker`, ротация логов | Выкл |
| 16 | `ollama` | Ollama | Локальный сервер LLM-моделей на `127.0.0.1:11434` | Выкл |
| 17 | `upgrade_ubuntu` | Новая LTS-версия | `full-upgrade` + `do-release-upgrade`; долго и требует перезагрузки, поэтому последний и выключен по умолчанию | Выкл |

### Защита от потери доступа
* `ssh_hardening` не запустится, если целевой пользователь — `root` или в его `authorized_keys` нет ни одного ключа. Это проверяется **до** начала установки.
* Порт SSH по умолчанию **не меняется**. Новый порт (`--ssh-port` или поле в меню) сначала открывается в UFW и в `iptables` (если там есть `REJECT`, как в образах Oracle Cloud), и только потом sshd переключается на него. Во внешнем файрволе провайдера (Security List / Security Group) порт нужно открыть самостоятельно.
* Конфиг пишется в `sshd_config.d/01-vps-setup-hardening.conf`: sshd берёт *первое* значение, а `50-cloud-init.conf` иначе оставил бы вход по паролю. После записи проверяется действующий конфиг (`sshd -T`); при несовпадении изменения откатываются.
* В Ubuntu 22.10+ (активация через `ssh.socket`) новый порт применяется через `daemon-reload` и перезапуск сокета.
* `fail2ban_ufw` открывает порты, на которых sshd реально слушает.

## Сборка

Нужен Go 1.24+.

```bash
make test             # go vet + go test -race
make build-linux      # x86_64 -> dist/vps-setup-linux-amd64
make build-arm64      # ARM64  -> dist/vps-setup-linux-arm64 (Oracle Ampere и т.п.)
make release          # обе архитектуры + checksums.txt
```

## Первый запуск на новом сервере (без графики)

Подключитесь по SSH и скачайте последний релиз под архитектуру сервера (amd64 или arm64):

```bash
curl -fsSLo vps-setup "https://github.com/itmaxk/crystal-core-vps-install-manager/releases/latest/download/vps-setup-linux-$(dpkg --print-architecture)"
chmod +x vps-setup
sudo ./vps-setup
```

Собранный локально бинарник можно передать и так: `scp dist/vps-setup-linux-amd64 ubuntu@<IP_СЕРВЕРА>:vps-setup`.

В первом окне выберите **«Быстрый старт — рабочий стол XFCE + вход по RDP»**. Если у пользователя нет пароля (как у `ubuntu` в облачных образах), установщик попросит его задать: RDP-вход возможен только по паролю. Остальные модули можно поставить позже, повторным запуском с выбором «Полная настройка».

То же без меню:

```bash
read -rs VPS_SETUP_PASSWORD && export VPS_SETUP_PASSWORD
sudo -E ./vps-setup --preset rdp                    # под пользователем ubuntu/opc
sudo -E ./vps-setup --preset rdp --new-user dev     # под root — создаст пользователя dev
```

### Подключение к RDP через SSH-туннель

```bash
ssh -p 22 -N -L 13389:127.0.0.1:3389 user@<IP_СЕРВЕРА>
```

Затем в RDP-клиенте (mstsc, Windows App, Remmina) подключитесь к `localhost:13389`, сессия **Xorg**, логин и пароль пользователя. Установщик печатает готовую команду с актуальным портом сразу после модуля `xrdp` и в конце работы.

## Флаги CLI

| Флаг | Описание |
|---|---|
| `--status` | Вывести таблицу состояния всех модулей (работает без `sudo`) |
| `--json` | Вывод статуса в JSON (используется совместно с `--status`) |
| `--preset <rdp\|full>` | Неинтерактивный запуск набора: `rdp` — рабочий стол + RDP, `full` — все рекомендуемые. Уже установленные модули пропускаются |
| `--only <list>` | Неинтерактивный запуск указанных модулей через запятую (`--only xfce,xrdp,docker`); можно сочетать с `--preset` |
| `--new-user <name>` | Имя пользователя для `create_user` в неинтерактивном режиме; пароль берётся из переменной `VPS_SETUP_PASSWORD` |
| `--user <name>` | Явно указать целевого пользователя (для `cloud-init` / Ansible под `root`) |
| `--ssh-port <port>` | Новый порт SSH для `ssh_hardening` (по умолчанию — текущий, без смены) |
| `--auto-reboot` | Отложенная перезагрузка (5 сек) в конце, если система её требует |
| `--dry-run` | Показать план команд и файлов без внесения изменений в систему |
| `--self-update` | Обновить бинарник из GitHub Releases (для приватного репозитория: `sudo -E env GITHUB_TOKEN=... ./vps-setup --self-update`) |
| `--version` | Показать версию и платформу |

| Переменная | Описание |
|---|---|
| `VPS_SETUP_PASSWORD` | Пароль нового пользователя (`create_user`) или пароль для RDP-входа текущего, если у него пароля нет |
| `GITHUB_TOKEN` / `GH_TOKEN` | Токен для `--self-update` из приватного репозитория |

Весь вывод системных команд пишется в `/var/log/vps-setup.log` (дописывается, права `0600`). Если модуль падает, остальные всё равно выполняются; в конце выводится список упавших и команда для их повторного запуска. Исключение — `create_user`: без пользователя дальше идти нельзя.
